How it works

The hard part isn't search. It's that contracts never use your words.

Ask for "termination for convenience" and the clause you need reads "either party may terminate without cause upon thirty days' notice." Searching for the phrase misses it. So does similarity search. So, it turns out, does the standard tool for ranking results — it compares wording, not meaning.

So the decision moved. Ranking still chooses what order to read the contracts in, but a model that knows "without cause" is convenience decides whether each one qualifies. That one change took a termination question from four matches to sixteen.

First

It translates the ask

"Can either party do a TFC" becomes proper contract language before anything is searched — and you see the translation, so you can tell whether it understood you.

Then

It picks the kind of question

One contract, the whole book, or fresh drafting language. It says which it chose and why, and you can overrule it.

Next

It looks two ways at once

Exact wording catches section numbers and figures. Meaning-based search catches the paraphrase. Both sets are merged before anything is read closely.

Finally

It answers, or it doesn't

Every statement is tied to a passage someone can go read. If the passages don't support one, you get a decline instead of a guess.

Proof

Quality is measured, not claimed.

Every change to the system is graded automatically against a set of contracts with known answers. If grounding slips or answers get slow, the change doesn't ship.

No proprietary data, ever

Every document is public contract data (CUAD, CC BY 4.0), with its licensing written down. A contract tool that can't say where its knowledge came from is a problem waiting to happen.
