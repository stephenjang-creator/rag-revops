Deal desks get asked the same two questions all day: what does this contract say about X? and which of our contracts have X? This tool answers both in plain English, shows the passages it used, and says "I don't know" instead of making something up.

What you can ask it

One box. It works out what you meant.

There's no mode to pick. Type the request the way you'd say it to a colleague and a router sends it to the right skill — and tells you which one it picked, and why.

Skill 01 Give me wording for this

"I need payment terms for net 30." It pulls the closest real language out of the contract book, drafts a clause you can paste into an order form, and cites every agreement it borrowed from.

Skill 02 Which contracts have this?

"Which contracts let us walk away for convenience?" It reads every contract in the book and returns the ones that qualify — including the ones that never use your words for it.

Skill 03 What does this one say?

Pick a single agreement and ask about it. The answer is drawn only from that document, with the passages shown — or an honest "not covered here."

How it works

The hard part isn't search. It's that contracts never use your words.

Ask for "termination for convenience" and the clause you need says "either party may terminate without cause upon thirty days' notice." Keyword search misses it. Embedding search scores it low. Even a reranker — the standard precision tool — scores it near zero, because it compares wording, not meaning.

So membership moved: the reranker still decides what order to read contracts in, but a model that knows "without cause" is convenience decides whether each one qualifies. That single change took one termination query from 4 matches to 16.

STEP 01 Translate the ask

"Can either party do a TFC" becomes proper contract language before anything is searched — and you see the translation.

STEP 02 Pick the skill

One contract, the whole book, or new drafting language — routed automatically, with the reasoning shown.

STEP 03 Retrieve both ways

Exact-term search catches section numbers and figures; vector search catches paraphrase. Results are fused on rank.

STEP 04 Answer or decline

Every claim is tied to a passage. If the passages don't support one, the answer is a decline, not a guess.

Proof

Quality is measured, not claimed.

Every pull request runs an automated grader over a golden set built from expert contract annotations. If grounding slips, latency balloons, or citations stop appearing, the build fails and the change can't merge.

No proprietary data, ever

The whole corpus is public contract data (CUAD, CC BY 4.0), with licensing documented in the repo. A contract tool that can't say where its knowledge came from is a governance problem.

Prompts live in version control

Not scattered through the code — so changing how the model is asked something is a reviewable diff, stamped on every trace it affects.

Built in Python, end to end

LangGraph orchestration, hybrid retrieval, Cohere embeddings and rerank, Claude for generation and judging. Typed, linted, and unit-tested.
